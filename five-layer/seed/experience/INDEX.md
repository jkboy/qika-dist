## 维护规则

- 新条目使用 [`templates/entry.md`](templates/entry.md)。表格保持 4 列、列序 `关键词 | 条目 | 触发现象 | 状态`；状态写 `active` 才会被 experience-retrieve 注入（其他词不注入）；关键词用 `、` 分隔。**列序与格式是扩展的解析契约**，改表头会让整库零注入（`qika doctor` 第 12 节会报）。
- 关键词只覆盖**失败形态**：工具名、错误关键字、失败现象词。四类禁区：
  1. **业务功能名 / 项目名 / 通用错误码 / 常见英文单词做单个关键词**——会撞上正常开发流量被反复误拦。
  2. **模型名 / AI 领域高频术语**（claude-\*、deepseek-\*、gpt-\* 等）——AI 工具类项目里遍布源码常量与日志，形态再像复合词也不特异。
  3. **OS 通用错误文案**（No such file or directory、Permission denied 等）——几乎每个无关报错都带，会把无关 ENOENT 记成复发。
  4. **解法词**（条目「结论」推荐姿势里的词）——减速带会把按结论写出的正确命令拦下。
- 匹配器兜底：裸字母单词、全大写常量、errno 短语不能单独触发，只参与 ≥2 个关键词配对；每个条目至少放一个复合词（带分隔符/数字/中文）保证可命中。
- **关键词必须是真实报错或命令里会字面出现的串**：英文按整串词边界匹配，描述性短语永远不会出现在工具输入或报错里。匹配文本 = 工具输入 + **仅报错时**的输出；成功的撰写类调用（写文档、给子代理/用户写的正文）不匹配。新建或改关键词后，拿真实报错原文验证一次能命中。
- 命中统计：`node ~/.pi/agent/extensions/experience-retrieve/stats.mjs`。RECUR≥2（注入后仍复发）或疑似误伤 → 先看 hits.log 的 `kw=` 归因，再收紧关键词或按 five-layer-governance 评估升层。环境持续型条目（要人工解除的故障）在解除前每次重试都命中，RECUR 不代表没遵守。
- 条目提升、过时或不再影响决策时，立即移出本索引并删除正文——退休即删，去向写进 git 提交信息，历史由 git 承担（FIVE-LAYER §6）。
- 具体生命周期见 [`README.md`](README.md)。
