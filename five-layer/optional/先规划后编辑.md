## 先规划后编辑

> 可选规则（`qika five-layer init` 放在这里，默认不生效）。它让 agent 在跨文件改动前先停下来等你确认计划——
> 喜欢这种节奏就把本节整段粘进 `~/.pi/agent/AGENTS.md`；不粘就当它不存在（注释掉也会被注入给模型，所以单独成文件）。

- 小改白名单（typo / 字符串字面量 / 注释 / 调试输出；单文件、<30 行、不改控制流、不改公共接口）→ 直接改。
- 命中任一：跨文件、新增模块、修改公共接口、修改控制流、影响范围不确定 → 先只读探索，产出计划（目标、改动点、必要性——每个新增的抽象/层/配置项各一句"删掉它哪条需求或约束会失守"、验证方式），经用户确认后再开始编辑。确认前唯一允许写入的是计划/任务文档本身。
- 计划落盘按 `task-tracker` skill 的触发条件：命中时写 task 文档，**task 文档即计划本体**，不另建第二份计划文件；未命中的轻任务把计划写在回复里等确认。checkpoint、压缩安全与恢复流程同样按 `task-tracker`。
