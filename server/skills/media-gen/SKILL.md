# 媒体生成（media-gen）

> 本技能随 Qika Code 内置，只在用户配置了图片或视频生成端点时出现。哪一块可用以工具列表为准：
> 有 `generate_image` 就能出图，有 `generate_video` 就能出视频。别在技能面板里停用它——那会改包内文件，更新后丢失；要停用请清空设置里的 Base URL。

## 1. 何时用 / 不用

- **用**：用户要一张不存在的图（海报、插画、配图、UI 占位素材、透明底图标、示意图）、要把已有图片改风格/改内容（图生图），或要一段几秒的视频片段（文生视频 / 从一张图起动）。
- **不用**：已有素材能直接用的先找（`generated/`、项目资源目录）；图表、流程图、简单几何图标能用 SVG / Mermaid / 代码画的不生成（可控、可改、免费）；需要精确排版大段文字的（长海报正文、表格）生成模型做不好，改用 HTML/CSS 渲染。
- 每次调用都花钱、都过用户审批。**没把握就先问，不要试着生成看看。**

## 2. 动手前的最小澄清

缺以下任一关键项且无法从上下文推断，用 `ask_question` 一次问清，不猜：

1. **用途与投放位置**（决定比例/尺寸）：网页横幅 → 横向；手机壁纸/短视频 → 竖向；头像/图标 → 正方形。
2. **风格**：写实照片 / 扁平插画 / 3D 渲染 / 像素 / 水彩……用户说不清就给 2~3 个选项让选。
3. **图中 / 片中文字**：要出现的文字**原文**（一字不差）和位置。没有就明确"无文字"。
4. **是否有参考图**：有就要路径（图生图 / 首帧 / 风格参考）。

视频额外问：**时长**（5s 还是 10s）与**是否需要镜头运动**。

## 3. 图片提示词（generate_image）

按这个顺序写一段完整、自足的英文或中文描述（模型看不到对话，只看 prompt）：

```
主体（是什么、几个、状态）→ 环境/背景 → 风格与媒介 → 构图/景别/视角 → 光线与色调 → 文字（原文 + 位置 + 字体感觉）→ 排除项（如 "no watermark, no extra text"）
```

- **文字必须原文放进 prompt 并加引号**："the sign reads 'OPEN 24H'"；生成后用视觉核对拼写。
- **尺寸**三档：`1024x1024` 方 / `1536x1024` 横 / `1024x1536` 竖。缺省用设置里的默认值；用途明确时显式传。
- **质量**：草稿/迭代用 `low` 或 `medium`（快、便宜），定稿再 `high`。
- **透明底**：`background: "transparent"`，输出格式需 png/webp（设置里格式若是 jpeg 要显式说明或改设置）。
- **编辑模式**：传 `referenceImages`（≤16 张）。prompt **只描述改动**（"把背景换成夜景，其他保持不变"），不要重新描述整张图。
- 一次只生成一张；要多个候选就调多次并改一个变量，方便用户对比。

## 4. 视频提示词（generate_video）

一段短片 = **一个主体动作 + 一个镜头运动 + 氛围**。不要写多镜头叙事、不要写对白。

```
[主体 + 正在做的动作]，[场景与光线]，[镜头：推/拉/摇/移/环绕/固定，一种]，[风格/质感]
例：一只橘猫在窗台上伸懒腰，午后阳光斜射，镜头缓慢推近，电影感浅景深
```

- **时长**：5s 够表达一个动作；10s 只在动作确有过程时用（按秒计费，贵一倍）。Seedance 2.5 经 OpenRouter 支持 4~30s、480p/720p、比例 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 21:9；超出范围上游直接拒。
- **比例**按投放：横屏 `16:9`、竖屏短视频 `9:16`、方图 `1:1`。
- **参考图**：`firstFrame` = 从这张图起动（图生视频，最常用）；`lastFrame` = 结束停在这张图；`referenceImages` = 主体/风格参考（不做首帧）。都是本地图片路径。同时给了首尾帧和参考图时以首尾帧为准（参考图被忽略）。
- **成本确认（必做）**：调用前把**最终提示词、时长、比例**用一两句话给用户看，得到同意再调。审批卡会再弹一次，但改措辞发生在这一步更省钱。
- 调用会阻塞几分钟并显示进度；若结果说 "still running" 并给了 `taskId`，**再调一次只传 `taskId`** 继续等，不要重新提交（会重复扣费）。

## 5. 迭代闭环

1. 生成 → 看结果：你有视觉就直接看；没有就 `vision_analyze` 带**具体问题**（"图中文字是否恰好是 'OPEN 24H'？""主体是否居中、有无多余肢体？"），不要问"描述这张图"。
2. 不满意时**每轮只改一个变量**（措辞 / 尺寸 / 质量 / 参考图），并告诉用户改了什么。
3. **3 轮仍不达标就停**，把已有候选摆给用户，重新对齐需求，而不是继续烧钱试。
4. 视频不做模型侧回看（没有抽帧通路）：生成完直接把路径给用户看，等用户反馈。

## 6. 产物与汇报

- 产物默认在 `<项目>/generated/<时间戳>-<提示词片段>.<ext>`；需要固定文件名时传 `outputPath`（相对项目根）。**项目目录外的路径聊天里无法预览**。
- 回复里**写出文件路径**（聊天会内联预览），多张候选时一句话说明各自差异。
- 首次在项目里生成时，问一次用户是否把 `generated/` 加进 `.gitignore`（二进制产物通常不该进仓库）；用户说要提交就别再问。
- 工具卡里能看到模型、耗时、任务 id 与上游原始错误；失败时把上游错误原话转给用户，别自行猜测原因重试超过一次。
